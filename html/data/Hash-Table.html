Hash Table

A hash table (or hash map) stores key–value pairs and retrieves them in average O(1) time. A hash function turns each key into an index — a bucket — where its value is kept, so a lookup jumps straight to the right slot instead of scanning.

Different keys can land in the same bucket — a collision — so every hash table needs a way to resolve them:

Collision resolution

  • Separate chaining: each bucket holds a small list; colliding entries are appended and searched by key. (This demo uses chaining, with index = number mod 10.)
  • Open addressing: on a collision, probe the following buckets until an empty one is found.

On average this beats search trees and other lookup structures — at the cost of storing nothing in sorted order.
